# Native material and lighting view — 7 November 2026

The studio adds a 3D appearance selector: Technical (fast, default) and Material
and light (native Design mode). JARVIS can also choose technical/design through
architecture_render. The backend validates the mode before queueing it; the
frontend acknowledges only after the current home's matching renderer has
drawn a frame. It reports the actual style, shadows and AO pipeline state.

This exposes the pinned editor's existing MeshPhysicalMaterial, sun shadows,
furniture light sources, image-based environment and GTAO pipeline. It does not
claim photoreal output, a new texture/material editor or stable FPS on all GPUs.
Technical remains the default for responsiveness. The selection is remembered
in this browser when local storage is available, rather than stored in SH3D
geometry. A failed remembered mode is cleared and shown in the status bar.

Corrections in the pinned GPL source/runtime integration:

- HomePane subscribes to native preference changes using a removable callback.
- Project replacement carries the view preference into the new session and
  updates the previously stale __preferences integration hook.
- HomeScene3D uses an actual THREE.Scene root, allowing Three.js to honor its
  scene background and environment texture. Previously it returned a Group
  with scene-only properties assigned through a cast.
- DesignComposer explicitly disposes each pass before the composer itself,
  releasing AO/output resources when changing modes.
- Render stats identify the active style and shadow/AO settings.

The mode adapter snapshots the observer pose and active camera, waits for the
matching native scene and drawn frame, lets its initialization callbacks finish,
then restores the pose and active camera. Failed changes revert the preference
and wait for fallback rendering before restoring the camera. It does not edit
geometry or append an undo transaction. Existing native edits/save/undo remain
on their established paths. Original vendor archives/hashes are unchanged;
exact corresponding source and rebuild patches are included (studio7).

Local validation: 13 architecture tests, four API/responsiveness tests, bridge
regressions, render-adapter tests, schema and tool-budget tests, production-bundle
JS syntax and Python compile checks passed. Render-adapter tests cover delayed
frames, invalid modes, observer/top camera retention and failed-mode rollback,
including delayed initialization callbacks. Local Chromium was attempted again
and failed before launch with socket EPERM. Hosted real-browser evidence is
required for actual PBR/lighting validation.
