# Design studio validation — 7 November 2026

Scope: additions on `feature/jarvis-4.8-design-studio`, PR #46. The complete
OMEGA specification is not implemented or claimed complete by this change.
No release/version bump or updater promotion is included.

## Implemented

- Measured furniture inspector uses native object IDs and atomic model commands;
  validates name, positions, dimensions and angles before submitting. Confirmed
  save/ACK precedes success; native history supports undo/redo.
- Explicit top/observer camera controls.
- Local SVG export of measured rooms, walls and rotated furniture footprints,
  escaped names and a view box covering rotated/outlying objects. Multiple
  floors project into the same plane; this is not a photoreal render.
- Lists up to 50 existing project snapshots; restores an exact stored revision
  via the same acknowledged UI queue, retaining the replaced current project.
  Revision lookup accepts only positive integers, not filesystem paths.
- Shared completion for concurrent saves. A serialization comparison preserves
  the dirty flag if a manual edit occurred during the disk/network operation.
  Autosave finishes before the next queued model mutation.
- Load the stored project before asking to replace an existing drawing.
- Local editor shell styling, accessible form labels/focus and reduced motion.
- Restored browser error assertions accidentally swallowed by literal `\n`
  sequences inside a comment; removed the same text artifact from the HTML.

## Browser-discovered fixes

The first CI attempt exposed a pre-existing compact-house test expectation that
excluded the corridor (the model has five room polygons). The second reached
the new inspector and its screenshot identified a real form-validation defect:
auto-generated positions contain fractional centimetres, while HTML step=.01
rejected an unchanged coordinate and prevented submission. Inspector numeric
fields now use step=any with the same range/finite-number validation. The browser
regression explicitly checks form validity before submitting. These failed runs
remain visible; neither was reported as a browser pass.

The next browser run passed measured inspector edits, both camera modes, actual
SVG download, atomic undo/redo, 1080p/1440p/4K screenshots and durable SH3D reload,
but timed out focusing the history selector after reload. History options now
load during editor initialization and after successful saves, without rebuilding
the native select options on focus. Restore is not claimed verified until the
complete scenario passes.

## Visible 3D interiors

Visual inspection also showed that default room ceilings and a low initial
exterior camera obscured the furniture. New bridge-created rooms now hide their
ceilings and the initial camera is elevated to 0.85 radians. Existing project
rooms retain their saved ceiling choice. The pinned distribution receives two
exact, fail-closed JS substitutions after archive SHA verification, in a separate
versioned extraction cache. Original vendor archives are immutable. The source
download now contains the corresponding modified TS files, and the rebuild
script applies those same source patches before compiling. Unit tests check
patch idempotency, exact bundle changes and corresponding source. This does not
claim PBR materials, photoreal rendering, a full wall-cut system or catalog previews.

## Serialization measurements

The software-WebGL run recorded typical state reads at 101–586 ms, house creation
at 30,742 ms, undo at 32,636 ms and redo at 33,268 ms. These are CI-specific
measurements; they are not hardware FPS or live model latency. Source inspection
found writeHome reading every content stream twice (digest + archive). The
serializer now retains each byte array for both uses, preserving digest/ZIP entry
order and reducing content reads from two to one per write. A subsequent run is
needed before claiming a measured wall-clock speedup.

The revision select exists and contains options after reload, but Playwright's
focus/select-option action still timed out. The end-to-end test now exercises
its native keyboard path (click, Home, ArrowDown, Enter), verifies the selected
revision against the server, and still requires the actual restore button and
new saved revision. No direct API substitute is used for the UI selection.
