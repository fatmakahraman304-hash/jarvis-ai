# Plan-icon buffer follow-up — 7 November 2026

The previous viewport work left repeated WebGL buffer allocation for different
plan-icon dimensions. The default shared icon renderer now retains a buffer
large enough for the largest width and height requested in this page, growing
each dimension only when necessary. Each icon sets its own exact viewport and
copies the corresponding lower-left buffer region into its separate 2D canvas.
Output dimensions, antialiasing, material settings and camera projection remain
unchanged. This does not share project-specific model caches across views.

The original runtime and source archives remain immutable. Exact source/bundle
substitutions, the updated source test double, and fail-closed/idempotence checks
are included. Runtime extraction/source revision is studio6.

Local validation: 12 architecture tests passed, including execution of the actual
patched minified icon method against a drawing-buffer double. Alternating icon
dimensions reuse the buffer, growth preserves both axes, and viewport/copy
coordinates match the requested output. Missing models/WebGL retain their null
fallback. Bridge save/error/concurrent-edit and viewport regressions, three
server-responsiveness tests, compiled production JS syntax and Python syntax
also passed. A fresh local Chromium launch failed with socket EPERM; real-browser
evidence must come from hosted CI.

The added real-browser assertion renders the same furniture into an exact-sized
buffer and then into an enlarged shared buffer. It compares every output pixel,
checks opaque/nonblank content, and verifies the small icon does not shrink the
shared buffer. The complete existing UI persistence/restore scenario also runs.
